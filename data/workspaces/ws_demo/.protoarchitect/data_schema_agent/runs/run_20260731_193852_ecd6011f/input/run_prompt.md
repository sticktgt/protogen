Синхронизируй все входные требования с текущей логической схемой данных.

Входной набор является текущим пакетом синхронизации и может быть неполным. Не считай отсутствующие в нём requirement ID удалёнными и не перестраивай корректную существующую схему только из-за их отсутствия.

1. Один раз вызови `load_synchronization_context`.
2. Выполни один внутренний проход проектирования по всем требованиям без отдельного tool call и без generation plan.
3. При необходимости вызови в порядке зависимостей:
   - `write_data_schema_dictionaries`;
   - `write_data_schema_core`;
   - `write_data_schema_relations`.
4. Проведи молчаливый финальный самоконтроль структуры по system-инструкции и исправь найденные пробелы специализированными patch-инструментами.
5. Ровно один раз вызови `write_data_schema_traceability`. Передай полный итог каждого входного requirement ID в одном массиве `updates`; каждый ID встречается ровно один раз. Для `direct` передай полный набор links. Для остальных classifications передай пустой `links`; `reason` обязателен только для `unclear`, а для `no_data` и `cross_cutting_data` может быть опущен.
6. Сразу после успешной записи полной трассировки заверши отдельным вызовом `validate_data_schema_state`.

Не создавай отдельные generation plan, concept mapping или audit-документы. Не создавай значения справочников из типичных примеров. Не используй трассировку как замену отсутствующей структуре схемы. Для требования уровня UI без предметных данных используй `no_data`; `cross_cutting_data` оставляй только для сквозных правил данных.
