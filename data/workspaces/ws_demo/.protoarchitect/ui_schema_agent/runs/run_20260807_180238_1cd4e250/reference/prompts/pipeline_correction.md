Используй только переданные требования, текущие решения, `audit_issues`, `technical_errors` и фактическую текущую схему. Не перегенерируй остальные решения и не повторяй уже применённые изменения.

`audit_issues` — повод перепроверить схему, а не приказ создавать объект. Для контейнера проверь всё поддерево и связи; `child_count` означает только непосредственных детей.
