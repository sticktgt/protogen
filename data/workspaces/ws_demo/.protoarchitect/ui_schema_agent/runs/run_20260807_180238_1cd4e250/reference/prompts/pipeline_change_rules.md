Общие правила для любого `changes`-пакета:

- Фактическая текущая UI-схема — единственный источник существующих ID, типов и родителей. `technical_index` является вычисляемым плоским представлением тех же данных: все перечисленные в нём цели уже существуют; верхние поля индекса показывают допустимые `action`, а запись элемента — текущего родителя и тип. Для `reuse` и `extend` копируй точный ID из схемы или индекса. `create` используй только для отсутствующей цели, создаваемой этим пакетом.
- Если техническая проверка сообщает, что цель уже существует, не повторяй `action=create`: используй `reuse`, когда цель не меняется, или `extend`, когда пакет обновляет существующую цель. Если `reuse`/`extend` указывает на отсутствующую цель, выбери точный существующий ID либо создай отсутствующую цель через `create` и соответствующую операцию.
- Нужен минимально достаточный прототип. По умолчанию сохраняй существующие страницы, элементы и их иерархию. Не перемещай существующий элемент только ради более аккуратной группировки, нового wizard/section или желаемой композиции, если обязательный результат можно показать на текущем месте.
- Новую страницу передавай в `create_pages`; метаданные существующей — в `update_pages`; элементы — в `upsert_elements`. Не создавай параллельный объект с тем же назначением.
- Вложенные `children` нового контейнера должны содержать только действительно новые элементы. Не вкладывай существующие элементы в новый контейнер как способ переноса: обновляй их отдельными upsert-операциями на текущем месте.
- Смена родителя существующего элемента допустима только через `move_elements` и только когда она действительно нужна требованию. Если элемент одновременно обновляется, в его `upsert_elements` опусти `parent_id` или укажи текущего родителя; новый родитель укажи только в `move_elements`. Новый контейнер можно создать тем же пакетом.
- При ошибке о неявном переносе выбери один вариант для каждого перечисленного элемента: сохранить текущего родителя и убрать попытку переноса либо добавить явный `move_elements`, если без переноса обязательный результат недостижим. Исправляй сразу весь список ошибок, а не только первый элемент.
- Используй только типы, scope и отношения из каталога; соблюдай `allowed_children`, `allowed_parents`, `root_allowed` и точные родительские ID. Тип с `root_allowed: false` нельзя размещать в корне страницы. Непосредственный ребёнок `table`, представляющий колонку, имеет тип `table_column`, а не `text`.
- Для `app.json` используй `page_id="app"`. В корне допустимы только типы с `root_allowed`; остальные app-типы размещай внутри разрешённого app-контейнера. Не создавай UI-элементы для обработчиков, форматтеров, сервисов, общих правил или шаблонов состояний.
- Источник `ui_links` — страница либо элемент с `link_source: true`. Не используй неинтерактивные контейнеры (`section`, `form`, `wizard`) как источник; выбери кнопку, ссылку или другой разрешённый интерактивный элемент. Для `opens_modal` цель должна быть `modal`.
- Для `direct_ui` нужна конкретная цель. Глобальный `cross_cutting_ui`, не требующий отдельного видимого объекта, может иметь пустые цели и не менять схему. Для `no_ui` используй `ui_effect=none` без целей; для `unclear` — `ui_effect=unclear` без целей.
- Если изменения не нужны, оставь операции пустыми и заполни `no_changes_reason`; не сочетай его с операциями. `warnings` используй только для неустранённого ограничения, требующего внимания человека, а не для обычного решения, `reuse`, `extend` или уже исправленной ошибки.
- После отклонения пакет считается полностью отменённым. Повторно проверь все его операции и решения, потому что одна техническая ошибка могла скрывать другие.
