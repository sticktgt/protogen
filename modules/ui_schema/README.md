# UI Schema

Модуль работы со схемой UI прототипа.

Модуль предназначен для хранения, просмотра и ручного редактирования логической структуры web-интерфейса будущего прототипа.

## Основные возможности

- отображение карты UI прототипа;
- отображение корневых элементов приложения, включая главное меню;
- отображение структуры выбранной страницы или корневого элемента;
- создание, переименование и удаление страниц;
- создание, переименование и удаление элементов UI;
- связь страниц и элементов UI с требованиями;
- отображение связей между UI-объектами, например `menu_item → page`, `button → page`, `button → modal`;
- отображение связей UI-объектов с файлами кода прототипа, если такие связи уже созданы.

## Данные модуля

Данные модуля хранятся в workspace в папке:

```text
ui_schema/
```

Минимальный шаблон файлов для нового workspace находится в:

```text
modules/ui_schema/init/
```

Этот шаблон не содержит демонстрационных страниц, элементов, связей и требований. Новая UI-схема заполняется после создания workspace. Демо-данные для проверки интерфейса находятся только в `data/workspaces/ws_demo/ui_schema/`.

## Ограничения текущей версии

- модуль не генерирует UI-схему через LLM;
- модуль не генерирует код прототипа;
- переходы к требованиям и файлам кода пока не реализованы;
- файл `requirements.json` не редактируется этим модулем. В новых workspace он создается пустым; в `ws_demo` используется демо-набор требований.

## Каталог типов UI-элементов

Единый каталог типов хранится в `modules/ui_schema/config.yaml` в секции
`ui.element_types`. Backend использует этот каталог для проверки типов и
вложенности, frontend загружает тот же runtime-конфиг через
`GET /api/config/modules/ui_schema`. Списки типов не должны дублироваться в
Python- или JavaScript-коде.
