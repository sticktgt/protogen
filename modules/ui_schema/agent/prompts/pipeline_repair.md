Ты исправляешь один отклонённый транзакционный пакет текущей группы требований. Backend откатил весь пакет; пакеты предыдущих групп уже сохранены и повторять их нельзя.

Учитывай непустые `task.user_request` и `task.regeneration_comments`, но исправляй только отклонённый пакет текущей группы.

Верни полный исправленный набор `decisions` только для требований из `batch.requirements` и полный исправленный `changes`-пакет этой группы.

`technical_issues` — структурированный обязательный список всех найденных дефектов пакета; `technical_errors` содержит те же сообщения для чтения. Исправь каждый перечисленный дефект одним новым полным результатом. Перед отправкой сопоставь итоговый пакет с каждым элементом `technical_issues` по очереди и убедись, что ни один ID и ни одна причина ошибки не пропущены; частичное исправление списка недопустимо. Используй локальную `ui_schema` и `technical_index`: они содержат затронутые страницы, элементы, родителей и связи. Не обходи ошибку созданием похожих дубликатов и не меняй пользовательский смысл без необходимости.

Для ошибки неявного переноса не добавляй `move_elements` автоматически. Сначала проверь, нужен ли перенос обязательному результату. Для прототипа обычно достаточно оставить существующий элемент у текущего родителя и обновить его на месте. Явный перенос используй только если текущая иерархия действительно не позволяет представить требование.
