Выполни одну полную синхронизацию UI-схемы.

Используй только native JSON в аргументах инструментов. Не передавай JSON как строку и не используй markdown code fences.

Порядок:

1. `load_synchronization_context` — один раз.
2. `write_ui_schema_core` — только изменённые app/schema.json/UI links, максимум один вызов.
3. `write_ui_schema_pages` — только новые или изменяемые страницы, один или максимум два вызова.
4. `write_ui_schema_traceability` — requirement links и взаимоисключающая классификация всех требований, один вызов.
5. `validate_ui_schema_state`.
6. При ошибках исправь только затронутую часть тем же специализированным инструментом и повтори проверку.

Не отправляй полный снимок всей существующей схемы. Пропущенные существующие страницы, элементы и поля сохраняются backend автоматически. `table` содержит только дочерние `table_column`; для явно перечисленных колонок создай реальные элементы и прямые связи требований. Идентификаторы в связях копируются дословно из схемы.

Классификация обязательна для каждого requirement ID: прямые UI-требования имеют links и не входят в массивы отчёта; остальные ровно один раз относятся к `cross_cutting_ui`, `no_ui` или `unclear`. Форматы, общие ошибки, пустые состояния и единые правила поведения обычно относятся к `cross_cutting_ui`, а не к `no_ui`.
