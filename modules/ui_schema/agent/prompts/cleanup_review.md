Проверь базовые объекты UI-схемы и верни не более {max_candidates} потенциальных кандидатов на ручную очистку. Все пояснения и рекомендации пиши по-русски.

Для каждого кандидата укажи:

- `category` — краткий тип проблемы;
- `message` — почему объект может быть неактуален;
- `recommendation` — что именно аналитику проверить вручную;
- `requirement_ids` — только связанные ID требований, если они известны;
- `targets` — один или несколько точных targets из `allowed_targets`.

Не добавляй кандидата только потому, что:

- requirement ID отсутствует в текущем входном файле;
- у элемента нет прямой requirement-связи;
- существует другой способ построить тот же интерфейс;
- объект кажется избыточным стилистически;
- текущий файл требований может быть неполным.

`summary` должен кратко описывать результат проверки. Если надёжных кандидатов нет, верни пустой `cleanup_candidates`.
