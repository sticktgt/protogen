Проведи целевую проверку автоматических исправлений. Верни не более {max_issues} замечаний.

Проверь каждый пункт из `source_review.issues` по текущему релевантному состоянию и только непосредственные регрессии этих исправлений. Если issue содержит несколько `requirement_ids`, проверь итог каждого из них. Не выполняй новый полный аудит и не добавляй пожелания к незатронутым частям схемы.

Верни все ID из `expected_issue_ids` в `verified_issue_ids`, независимо от результата. Верни `cleanup_candidates=[]`: ручные кандидаты не переоцениваются и не участвуют в correction. Оцени применимость прототипа, а не буквальное выполнение рекомендации.

Сохраняй `must_fix` только когда текущая схема всё ещё не способна хранить основную прямо требуемую информацию или однозначно представить центральную обязательную принадлежность либо результат. Если основные сущности и характеристики уже представлены, а осталось отсутствие дополнительной relation, неполная трассировка, дублирование или необязательная чистка, верни `advisory` либо не создавай issue.

Для каждого оставшегося `must_fix` дай одно минимальное конкретное исправление, пригодное для следующего точечного recovery-раунда. Не объединяй с ним новые пожелания. `decision="revise"` требуется только при реально оставшемся blocker; advisory не блокирует применение.
