Проведи проверку внутренней смысловой согласованности кандидата. Верни не более {max_issues} сгруппированных замечаний.

Двигайся от схемы к требованиям и проверяй только существенные дефекты:

- выбранная конструкция способна хранить основные характеристики, ради которых объект создан;
- поля-ссылки, relations, роли и cardinality не создают прямого противоречия;
- одно обязательное понятие не представлено двумя несовместимыми активными источниками истины;
- объекты имеют основание в требованиях;
- данные, которые требования прямо называют обязательными, не сделаны необязательными без основания;
- вычисляемые данные не дублируются как независимые обязательные факты без требования.

Не проверяй полноту requirement links и classifications. Не требуй идеальной нормализации, default, промышленной истории или единообразия.

Отсутствующая relation между уже существующими сущностями является `must_fix` только когда без неё нельзя однозначно представить прямо требуемую центральную принадлежность или результат. Если обе сущности и основные атрибуты уже существуют, а relation улучшает только навигацию, удобство выборки или аудит, это `advisory`.

Не предлагай удалять удобную прямую ссылку только потому, что тот же объект можно получить через цепочку других связей. Простое лишнее или устаревшее поле при наличии полноценной основной конструкции — максимум advisory.

Не рекомендуй новый справочник лишь потому, что похожее поле использует справочник. Справочник оправдан явно заданным управляемым набором или перечисленными значениями. Значение dictionary поддерживает только `id`, `title`, `description`; дополнительные характеристики требуют сущности.


Отдельно можешь вернуть до {max_issues} `cleanup_candidates` для ручной проверки аналитиком. Используй их только для существующих полей, сущностей, relations или справочников, которые выглядят явно устаревшими, заменёнными другой активной конструкцией или больше не поддерживаются актуальным набором готовых требований. Эти записи не являются issues, не влияют на решение и не должны формулироваться как команда агенту. Если конструкция остаётся применимой, а вопрос сводится к её возможной избыточности или ручному удалению, верни только `cleanup_candidate`, без advisory issue и без автоматической correction.

Для этого режима `verified_issue_ids=[]`. Установи `coverage_complete=true` только после проверки всей переданной схемы.
