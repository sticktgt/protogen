Сформируй один минимальный исполнимый план для issues из текущего review.

Посмотри `correction_context_json.correction_round`:

- в раунде 1 исправь все `must_fix`, затем совместимые конкретные advisory;
- в раундах 2 и далее исправляй только переданные оставшиеся blockers, по одному минимальному итоговому изменению на issue; не меняй незатронутую схему и не выполняй advisory.

Объедини операции в единственный вызов `submit_data_schema_semantic_correction`.

Правила плана:

- всем новым объектам, полям и значениям задай явные английские `snake_case` ID;
- новые верхнеуровневые объекты передавай в `write_*`, существующие объекты и новые вложенные элементы — в `patch_*`;
- новые relations передавай после сущностей в `write_relations`;
- удаляй только targets из `removable_added_targets`; ID-only patch ничего не удаляет;
- для каждого затронутого requirement ID передай полный итог в `requirement_updates`;
- сначала используй подходящие существующие targets из `candidate_schema_catalog`; создавай структуру только когда данные действительно негде хранить;
- не добавляй произвольные поля в значения dictionary и не придумывай отсутствующие значения;
- `summary` должен точно соответствовать операциям плана.
